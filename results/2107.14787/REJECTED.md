# Rejected at Step 0: arXiv 2107.14787

Paper: Dave Witte Morris, [*On hamiltonian cycles in Cayley graphs of
order pqrs*](https://arxiv.org/abs/2107.14787) (2021).

## Decision

No generator is shipped. A discarded prototype is retained as
`rejected_gen_2107_14787.py` for audit, as required when a build reaches code.
The paper-native Hamiltonian-cycle task can satisfy
**G** and **V**, but it fails **H on Track A**, and the paper's constructive
cases also fail the separate **Track B** test. This is an H rejection, not a
witness-rule rejection and not an answer-cap rejection.

The decisive Step 0 question is answered explicitly in Section 3, Case 2. For
a two-element generating set `A = {a,b}`, write

`b = a^k gamma`, with `gamma` generating the cyclic commutator subgroup `G'`.

The proof displays the quotient cycle

`C = (b, a^(-(k-1)), b, a^(p-k-1))`.

It proves that the voltage of `C` generates `G'`, and the Factor Group Lemma
(Lemma 2.4) says that `C` repeated `|G'|` times is a Hamiltonian cycle in the
original Cayley graph. Thus the certificate-producing algorithm is the
displayed formula itself. It does not search for a Hamiltonian cycle.

## What the paper actually proves

Definition 1.1 makes the native input a finite group `G` and a generating set
`A`. The vertices of `Cay(G;A)` are group elements, and `g` and `h` are
adjacent exactly when `g^-1 h` is in `A` or `A^-1`. Theorem 1.3 states that
every connected Cayley graph whose order is a product of four distinct odd
primes has a Hamiltonian cycle.

The exact regimes that make the theorem easy are central to the proof:

- Theorem 2.2 disposes of `|G'|` equal to 1, one prime, or two distinct primes.
- Lemma 2.6 says that for square-free order, both `G'` and `G/G'` are cyclic,
  and supplies the noncentrality facts used by the voltage arguments.
- Proposition 2.7 handles irredundant generating sets of size at least four.
- Section 3, Case 1 reduces through a normal cyclic subgroup to the already
  solved orders in Theorem 1.2.
- Section 3, Case 2 gives the displayed two-generator cycle directly.
- Section 3, Case 3 gives at most a small number of displayed quotient cycles
  in each subcase and proves that one has generating voltage.

These are existence and direct-construction results. The paper states no
computational-hardness theorem, average-case theorem, or hard distribution for
finding Hamiltonian cycles in these Cayley graphs.

## Exact native audit instance

To measure the most promising theorem-backed family, take

- `p = 3`, `q = 7`, `r = 13`, and `s = 19`;
- `m = q*r*s = 1729`;
- `G = C_m semidirect C_p`, generated by `gamma` and `a`, with
  `a gamma a^-1 = gamma^653`;
- `653 mod (7,13,19) = (2,3,7)`, so the action has order three and is
  nontrivial on every prime factor; and
- `A = {a,b}`, where `b = a^2 gamma`.

This is the difficult commutator regime of Section 3:
`G' = C_7 x C_13 x C_19`, and `G/G' = C_3`. Case 2 gives

`C = (b, a^-1, b)`.

An exact multiplication check gives voltage `gamma^1076`, and
`gcd(1076,1729) = 1`. Therefore Lemma 2.4 makes `C^1729` a Hamiltonian cycle.
Direct expansion was also checked: it visits 5,187 distinct vertices and
returns to the identity after 5,187 steps.

The natural compact JSON witness is only

```json
{"runs":[["b",1,1],["a",-1,1],["b",1,1],["a",1,0]],"repeat":1729}
```

It is 65 characters and 13 scalar atoms. A verifier can expand the runs and
check every group product exactly. This avoids the explicit-cycle answer cap,
but it also exposes why the family is easy.

## Mechanical cost versus compact route

The required Track B comparison was measured on the audit instance above.

| quantity | measured value |
|---|---:|
| group order / expanded cycle steps | 5,187 |
| compact certificate | 4 runs and one outer repeat |
| compact JSON size | 65 characters, 13 scalar atoms |
| arithmetic to obtain run lengths when `p,k,m` are present | 2 subtractions |
| arithmetic including `m=q*r*s` | 2 multiplications + 2 subtractions |
| other work | write the 13 certificate atoms |
| measured constructor time | 1.195 microseconds median |
| measured expanded-word time | 18.177 microseconds median |
| compact route | the same 2 subtractions and the same displayed word |

The timing used eleven rounds, with 500,000 compact constructions per round
and 5,000 expansions per round, on this runner. The exact times are not the
hardness claim; the important fact is the operation ratio of 1. The paper's
mechanical certificate algorithm and the proposed by-hand shortcut are the
same formula.

A second audit applied the retained prototype's own reference constructor to
its nominal shipping instance.  That instance has 139,133,387 vertices, but
the constructor found and exactly verified the 8-run certificate after one
orientation trial in 0.000061 seconds.  Its serialized answer was 96
characters.  Materializing 139,133,387 walk steps would be expensive, but it
is verification/output expansion, not the algorithm that produces the
certificate; counting it as the Track B reference route would compare two
different tasks.

Counting a generic exponential Hamiltonian-cycle search as the Track B
reference algorithm would be misleading. The domain-standard algorithm for
this generated regime is the paper's own Case 2 construction. It emits the
compressed witness in constant arithmetic work. Expanding the repeated word
is linear in 5,187 only because an explicit verifier must inspect 5,187 edges;
that expansion is not the algorithm that *finds* the certificate.

## Why Track A fails

Track A requires evidence that no efficient general method is known for the
generated distribution. Theorem 1.3 is not such evidence: it proves universal
existence, not search hardness. More decisively, the natural theorem-backed
two-generator distribution is solved on every instance by the displayed
Case 2 formula. The domain-standard attack would therefore succeed on every
seed, so it cannot appear as a failing Track A adversary.

The more involved three-generator subcases do not rescue Track A. They list
one or two short quotient words and use exact voltage tests to select a lift.
That is again a bounded constructive procedure, not a hard generated
distribution. Cases delegated to Theorems 1.2 and 2.2 do not provide a new
paper-backed hardness claim either.

## Why Track B also fails

Track B requires a large gap between an acknowledged efficient mechanical
algorithm and a short structural route. Here the short structural route is
already the mechanical algorithm. At the measured order 5,187, both routes
perform the same two run-length subtractions (four arithmetic operations if
the three-prime product is recomputed) and emit the same constant-size word.
Increasing the primes enlarges only the repeat count. It does not enlarge the
certificate-production cost or create anything for a solver to discover.

Requiring all 5,187 vertices instead would manufacture a transcription task:
indeed, even the smallest possible order under Theorem 1.3 is
`3*5*7*11 = 1155`, already above the 256-atom limit. Symbolic run notation is
both mathematically faithful to Notation 2.1 and cap-compliant, so this is not
`cap_bound`; it is simply too easy to produce.

## Audit of the prior planted-cycle proposal

The prior triage suggested planting a Hamiltonian cycle. That does not yield
an acceptable hard family from this paper:

1. Planting the Section 3 cycle preserves the native Cayley-group objects and
   gives a certificate by construction, but the Case 2 formula recovers it
   immediately.
2. Planting an arbitrary permutation cycle in an arbitrary graph discards the
   Cayley-group regime. It would be a convenience graph benchmark, not a
   paper-licensed reduction or native coverage of Theorem 1.3.
3. Adding every group difference used by an arbitrary planted cycle to `A`
   usually makes `A` large and the Cayley graph dense. The paper supplies no
   theorem that this planted distribution is hard, and worst-case Hamiltonian
   complexity would not establish distributional hardness.
4. Randomly relabelling the graph either retains the group operation, in which
   case the quotient/voltage construction remains available, or hides the
   group operation, in which case the paper's load-bearing group structure has
   been compiled away. A full relabelled vertex list is also unwritable, while
   a compact relabelling formula merely introduces an artificial decoder not
   present in the paper.
5. Encoding the cyclic quotient so that recovering `k` is a discrete-logarithm
   problem can hide the Case 2 formula, but it supplies no short solver route:
   the intended computation is then the same discrete logarithm. The paper
   gives no sub-300-operation invariant that recovers it. This would therefore
   fail Track B's compression requirement (and the no-tool effort cap), while
   a planted side channel revealing `k` would be an external puzzle rather
   than the paper's mathematics.

Case 3's choice between two displayed voltages is also not a standalone hard
answer language: if the requested witness is merely which of the two cycles
works, a structure-aware random candidate succeeds with probability at least
one half. Returning the whole compressed cycle enlarges the syntax but does
not change the two-candidate semantic search.

## Gate diagnosis

| requirement | result |
|---|---|
| G -- known certificate by construction | **Passes in isolation:** Section 3 plus Lemma 2.4 produces a compact Hamiltonian word. |
| V -- exact witness verification | **Passes in isolation:** expand the word, multiply in the finite group, check each vertex exactly once, and check return to identity. |
| H -- Track A | **Fails:** the paper proves no hard distribution, and its direct constructor solves the natural generated regime on every instance. |
| H -- Track B | **Fails:** mechanical and compact routes coincide; 2 subtractions versus the same 2 subtractions at the measured instance. |
| Overall | **Rejected by the mandatory Step 0 audit; the retained prototype should not be shipped.** |

The earlier prototype, its self-test report, `.meta.json`, and hardening
transcripts are retained only to make this decision reproducible, as the task
requires for a build that reached code.  The reference algorithm recorded in
that self-test solves 8/8 instances and is the evidence for this H rejection.
The oracle transcripts contain only HTTP 403 key-limit errors, which do not
count as model failures and provide no hardness evidence.  The prototype's
former `gen_` name was removed so it cannot be mistaken for a deliverable.
