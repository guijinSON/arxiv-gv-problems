## What this is and why it is trustworthy

[Jeff Shriner, *Hardness Results for the Subpower Membership Problem*](https://arxiv.org/abs/1707.08244) defines `SMP(A)` in Section 1. For a fixed finite algebra `A`, the input is a list of tuples and a target tuple in `A^m`; the question is whether a term in the generators equals the target. This module uses the paper's objects directly with `A = C_1019`, the additive cyclic group. Generator `j` has a field label `a_j` and is the exact tuple `(a_j^0, ..., a_j^(m-1)) mod 1019`. A submitted coefficient vector is a collected group term, and `verify` evaluates it coordinate by coordinate with exact integer modular arithmetic.

Generation is inverse, not search. It chooses an odd arithmetic progression of labels, assigns coefficient one to its members, and evaluates that term to make the target. Decoys and planted labels have the same uniform marginal distribution, and the labels are shuffled. The verifier never reads `inst["answer"]`; it accepts every coefficient vector that evaluates to the target. Determinism, JSON round-tripping, corruptions, density, attacks, scaling, and relabellings are all covered by `selftest()`.

## Why Track B, not Track A

Section 1 explicitly lists finite groups among the polynomial-time SMP regimes. The module therefore makes no Track A claim from Theorem 3.1's EXPTIME transfer. General group SMP is solvable by modular row reduction. On this generated distribution an even stronger construction-aware algorithm applies: Newton identities recover the monic polynomial of the unit-coefficient labels, then a Vieta root scan tests all displayed labels. Its complexity is `O(k^2 + nk)` field operations. At the shipping preset it succeeds 8/8, costs exactly 2,783 counted modular operations per instance, and took 0.001026 seconds total for the eight measured runs.

The compact route recognizes more: the selected labels are `c-hd, ..., c, ..., c+hd`. Their first power sum gives `c`, and their second gives `d^2`; because `1019 ≡ 3 (mod 4)`, one fixed modular exponentiation extracts `d`. Looking up those labels produces the sparse term in at most 92 exact arithmetic operations. Without noticing that symmetry, even the specialized mechanical route is far beyond unaided in-context calculation.

## Worked demo (`demo`, seed 0)

Here is the rendered problem in full.

```text
Subpower membership term over the fixed cyclic group C_1019

C_1019 is the set of residues 0,...,1018 with addition and negation modulo
1019.  Its direct power C_1019^8 consists of length-8 residue vectors, and
all group operations on these vectors are coordinatewise.

There are 11 generators, indexed 0 through 10.  Their field labels, in
generator-index order, are:
[468, 864, 778, 991, 499, 241, 525, 431, 266, 914, 41]

The coordinate exponents, in coordinate order, are:
[0, 1, 2, 3, 4, 5, 6, 7]

Generator j is defined exactly by
    g_j[r] = (label[j] ** exponent[r]) mod 1019
for every coordinate index r from 0 through 7.  In particular, exponent
zero uses a**0 = 1 even when a=0.  This formula is the complete generator data;
there are no omitted or approximate values.

The target vector, in the same coordinate order, is:
[3, 554, 525, 72, 971, 830, 87, 175]

Find any coefficient vector c such that
    target[r] = sum(c[j] * g_j[r] for j=0..10) mod 1019
for every coordinate r.  This is a collected group term witnessing that the
target belongs to the subalgebra generated by the displayed tuples.

Your answer must be one JSON list of exactly 11 integers.  Entry j is the
coefficient of generator j and must be in the inclusive range 0..1018.  Order
therefore matters, coefficients may repeat, and all indexing is zero-based.

Give your final answer inside <answer></answer> tags, as a JSON integer list.
Example syntax for a four-generator instance: <answer>[0, 1, 0, 1018]</answer>
Output nothing else inside the tags.
```

The answer is `<answer>[1, 1, 0, 0, 0, 1, 0, 0, 0, 0, 0]</answer>`, and `verify` returns `(True, "ok")`. Swapping positions 0 and 2 gives `[0, 1, 1, 0, 0, 1, 0, 0, 0, 0, 0]`; verification returns `(False, "coordinate_1_exponent_1_mismatch_expected_554_got_864")`. A person can solve this demo on paper: the three chosen labels have center `864`, and the other two labels sum to `2·864 = 709 mod 1019`, namely `468 + 241`.

## Caveats

This is deliberately not an average-case complexity result and should never be cited as one. A CAS, the disclosed Newton/Vieta scan, or ordinary modular linear algebra makes the family easy; it is useful only under the stated no-tool Track B evaluation. The `0/200,000` guess result samples uniformly from all coefficient vectors after imposing the freely visible exponent-zero sum. It does not model a solver's sparse or arithmetic-progression prior, so the exact density is evidence against blind coefficient guessing, not against insight-driven guesses.

The attack panel does not include an external CAS/SMT implementation or a timed dense Gaussian elimination; the successful specialized reference is stronger for this distribution and is reported instead. The canonical key handles generator order, coordinate order, and every affine label map `a -> ua+t` that preserves the generated Vandermonde family, but it is not a canonical form for arbitrary finite-group SMP instances or arbitrary `GL(m,1019)` changes that leave this presentation family. Finally, one of three bare shipping failures was a response-budget exhaustion, so the clean content-based bare evidence is two invalid answers, not three.
