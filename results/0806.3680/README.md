## The problem

The source is Bjarke Hammersholt Roune, [“The Slice Algorithm For Irreducible
Decomposition of Monomial Ideals”](https://arxiv.org/abs/0806.3680). The solver
receives the complete minimal generating set of an artinian monomial ideal:
pure powers `x_i^(c_i+1)` and explicitly listed quadratic monomials `x_i*x_j`.
It must return one maximal standard monomial `d`, meaning `d` is outside the
ideal while every `d*x_i` is inside it. Section 2.2 identifies these monomials
as a socle basis and maps them bijectively to irreducible components. The
answer is a sparse list of exactly eight nonzero variable/exponent pairs.

Verification is independent of the plant. It checks the grammar and caps,
proves that no displayed generator divides `d`, and proves that a displayed
generator divides each `d*x_i`. These are exact integer comparisons; no CAS,
floating point, search, or appeal to the paper occurs in `verify`.

## Construction and Track B hardness

Generation samples variable classes, keeps at least one class at the requested
eight-factor size, and chooses one capped monomial per class first. Intersecting
their irreducible pure-power ideals gives exactly the published generators: one
cap-crossing pure power per variable and `x_i*x_j` for every cross-class pair.
Thus the answer is known before the input ideal is assembled. Random transfers
vary the class-size multiset, so seeds remain structurally distinct even after
variable relabelling and the paper’s exponent-order remapping.

Track A would be false. Section 3 gives a terminating Slice Algorithm, Section
5 supplies pivot strategies, and Section 7 benchmarks Frobby against
Alexander-dual and Scarf-complex implementations. For this narrower “find one
size-eight maximum” task, a simpler reference algorithm builds incidence from
the quadratic generators and selects a variable whose non-neighbour class has
size eight. At shipping it solves 8/8 instances in about 0.0008 seconds after
an average 5,757 pair inspections and 11,514 endpoint comparisons, with
complexity `O(|min(I)| + n)`.

The intended no-tool route ignores the roughly 49,000-character generator
list. Section 4.7 observes that exponent order rather than magnitude controls
the decomposition. Here the caps also carry a planted affine invariant:
modulo the largest cap, `c_i - i*c_1` is constant on each coordinate class.
Bucketing 112 caps takes at most 224 exact field operations and yields any
size-eight support. The gap is about 5,757 list inspections versus 224
arithmetic operations, if the invariant is noticed.

The paper’s easy regimes were checked explicitly. Section 3.2’s square-free
base case does not apply because the ideal has non-square-free pure powers;
Section 4.2’s independence split does not apply because the mixed generators
connect every nontrivial variable partition; Section 4.3’s two-variable formula
does not apply; and the generator count is far above Section 4.1’s simplified
`|min(I)| <= n` base case. Large exponent digits are not claimed as hardness,
in accord with Section 4.7.

## Worked demo

For `make_instance(seed=0, n=6, block_size=2, calibration_prime=13)`, the full
rendered instance is:

```text
Find a maximal standard monomial of prescribed support size in an exact monomial ideal.

Definitions. Work in a polynomial ring K[x_1,...,x_6] over an arbitrary
field K. A monomial is x_1^a_1...x_6^a_6 with nonnegative integer
exponents. A monomial u divides v when every exponent of u is at most the
corresponding exponent of v. The monomial ideal generated by a list G contains
exactly the monomials divisible by at least one member of G. A monomial d is
standard when d is not in the ideal. It is maximal standard when d is standard
but d*x_i belongs to the ideal for every i=1,...,6. The support of d is the
set of indices i whose exponent in d is positive.

The ideal I below is given by its complete minimal generating set. First, for
every i it contains the pure power x_i^(c_i+1). The caps c_i are:
  1:10 2:13 3:4 4:13 5:10 6:1

Second, for every pair (i,j) in the following complete list it contains the
quadratic generator x_i*x_j. Pairs are unordered, their displayed indices are
1-based, and no unlisted quadratic monomial is a generator:
  (1,5) (2,4) (1,4) (2,5) (3,4) (1,2) (4,6) (2,3) (5,6) (3,6) (1,6) (3,5)

There are 18 minimal generators in total.

Return one maximal standard monomial whose support has exactly
w=2 nonzero factors, in sparse JSON form. Write
[[i_1,e_1],...,[i_w,e_w]], where 1 <= i_1 < ... < i_w <= 6, there are no
repeated variables, and e_t must equal the displayed cap c_(i_t). Every
unlisted variable has exponent zero. Order inside the list matters only for the
required increasing-index canonical format.

Give your final answer inside <answer></answer> tags, as one JSON list of
exactly 2 [variable_index,exponent] pairs. A syntax-only
example (not asserted to solve this instance) is
<answer>[[1,10],[2,13]]</answer>
Output nothing else inside the tags.
```

The missing quadratic pair `(4,5)` gives
`<answer>[[4,13],[5,10]]</answer>`. The module reports
`verify(inst, inst["answer"]) == (True, "ok")`. Dropping the second factor
reports `(False, "expected exactly 2 nonzero factors")`. This demo is genuinely
hand-solvable: list the three missing pairs and choose any one.

## Caveats

The exact random-guess density applies to the declared prior: a uniform
eight-variable support with exponents already fixed to their caps. It says
nothing about a solver using cap residues or mixed-generator incidence. Both
routes solve every instance efficiently with tools; that is why this is Track B.

Frobby, Macaulay 2, Monos, a modern CAS, and a full Slice implementation were
not run. They compute more than this one-witness task, while the incidence scan
is already a stronger specialized baseline for this distribution. The modular
cap invariant is generator-specific rather than a theorem of the paper,
although the inverse intersection and witness definition are native. The large
rendered pair list may test visual bookkeeping as well as insight; the
81-character conservative witness bound and 224-operation compact route remain within
the no-tool caps. Finally, the current two-model pool is narrower than the
four-vendor pool described in the supplied task, and the missing placebo arm
prevents the intended controlled estimate of the hint’s effect.
